# 맛소금 개인 웹 페이지 개편 디자인

## 목표

현재 페이지가 가진 산 풍경, 이름, 릴케의 시, 프로젝트와 외부 글 링크를 유지하면서 가끔 쓰는 개인적인 생각을 직접 발행할 수 있는 개인 웹 페이지로 개편한다. 첫인상은 포트폴리오보다 사람과 생각에 무게를 두며, 글이 많지 않아도 비어 보이지 않는 구성을 지향한다. 기존 BootstrapMade 템플릿의 구조와 표현은 재사용하지 않는다.

## 확정된 방향

- 시각안은 `A. 짧은 풍경, 이어지는 생각`을 사용한다.
- 기존 전면 산 사진은 유지하되 화면 전체 높이에서 약 절반 높이의 도입부로 줄인다.
- 최신 기록이 산 사진 바로 다음에 보여야 한다.
- 릴케의 시와 그 뒤의 개인 문장은 하나의 Article로 발행한다. 시를 위한 별도 메뉴나 전용 섹션은 만들지 않는다.
- 기존 여섯 개 콘텐츠 링크의 URL을 모두 유지한다.
- 개인 글은 저장소의 Markdown 파일로 발행한다.
- 첫 Article은 `젊은 시인에게 주는 충고` 전문과 기존 문장인 “때때로 검색과 댓글의 성급한 해답 말고 / 온전히 내 자신의 해답이 필요하다.”를 함께 담는다.
- 사이트는 기존 Bootstrap, Bootstrap Icons, Boxicons, AOS, Isotope, GLightbox, Swiper를 로드하지 않고 새 HTML/CSS와 필요한 최소 JavaScript만 사용한다.

## 정보 구조

홈은 다음 순서로 구성한다.

1. 상단 탐색: `맛소금`, `Project`, `Article`
2. 도입부: 산 사진 위에 이름과 짧은 소개
3. Article: 최신 글 한 편을 크게 보여주고 이전 글은 간결한 목록으로 제공
4. Project: 현재 프로젝트, 책, 브런치, 블로그 링크
5. 하단: 짧은 저작권 문구

상단 탐색은 한 페이지 안의 `Project`와 `Article` 영역으로 이동한다. 개별 글 페이지에서도 같은 상단 탐색을 사용하고 `맛소금` 링크로 홈에 돌아올 수 있게 한다. 홈에서는 사람과 생각을 우선하기 위해 Article을 Project보다 먼저 보여주되, 메뉴 표기는 사용자가 제시한 `Project`, `Article` 순서를 따른다.

## 시각 디자인

전체 방향은 차분한 개인 문예지에 가까운 편집 디자인으로 한다. 장식적인 카드 나열보다 타이포그래피, 가는 구분선, 충분한 여백으로 콘텐츠 층위를 만든다. 기존 템플릿의 청록색 포인트, 필터 탭, 이미지 오버레이 카드, 원형 버튼 표현은 이어받지 않는다.

- 산 사진 도입부는 데스크톱에서 약 `56svh`, 모바일에서 약 `48svh`로 제한한다. 다음 영역의 시작이 첫 화면에 보이도록 한다.
- 도입 문구는 `맛소금`과 “지구별에서 소프트웨어를 만들고, 때때로 생각을 적습니다.”로 구성한다.
- 제목과 Article 본문에는 한국어 명조 계열, 본문 보조 정보와 탐색에는 가독성 높은 고딕 계열을 사용한다.
- 색은 밝은 회백색 바탕, 짙은 숯색 본문, 녹슨 적색 포인트, 낮은 채도의 녹색 보조색으로 구성한다.
- 최근 기록은 별도 카드 테두리 없이 넓은 본문 열과 날짜, 제목, 도입 문장으로 보여준다.
- Project는 여섯 개 기존 링크를 하나의 편집형 목록으로 재구성한다. 각 항목의 성격은 작은 레이블로 구분하고, 기존 이미지는 썸네일로 사용하며 항목 전체를 클릭할 수 있게 한다.
- 등장 애니메이션은 도입부와 섹션 제목에만 짧게 적용하며 `prefers-reduced-motion`을 존중한다.

## 글 발행 구조

GitHub Pages의 기본 Jekyll 처리를 사용한다. Markdown 원본은 GitHub Pages 배포 시 정적 HTML로 생성되므로 브라우저에서 Markdown을 해석하는 라이브러리나 별도 CMS는 사용하지 않는다.

- `_posts/YYYY-MM-DD-slug.md`: 글 본문과 front matter를 저장한다.
- `_layouts/default.html`: 완전히 새로 작성한 공통 문서 구조, 메타데이터, 상단 탐색, 하단 영역을 담당한다.
- `_layouts/post.html`: 개별 글의 제목, 날짜, 본문, 홈으로 돌아가는 링크를 담당한다.
- `index.html`: Jekyll의 `site.posts`를 사용해 최신 글과 이전 글 목록을 렌더링한다.
- `_config.yml`: 사이트 URL, 언어, permalink와 기본 메타데이터를 정의한다.
- `Gemfile`: 로컬 빌드가 GitHub Pages 환경과 맞도록 `github-pages` 의존성을 정의한다.
- `assets/css/style.css`, `assets/js/main.js`: 기존 내용을 교체하고 새 디자인과 최소 상호작용만 담는다.
- `README.md`: 새 글 파일 이름과 front matter 작성 방법을 짧게 설명한다.

배포는 GitHub Pages의 내장 Jekyll 빌드를 전제로 한다. 별도 배포 워크플로는 현재 Pages 설정으로 빌드되지 않는 경우에만 추가한다.

글 front matter는 다음 필드만 요구한다.

```yaml
---
layout: post
title: "젊은 시인에게 주는 충고"
date: 2026-08-10
description: "때때로 검색과 댓글의 성급한 해답 말고, 온전히 내 자신의 해답이 필요하다."
---
```

카테고리, 태그, 검색, 댓글, 관리자 화면은 글이 드물게 올라오는 현재 범위에는 추가하지 않는다.

## 콘텐츠와 링크 보존

다음 URL은 변경하지 않는다.

- `https://github.com/msaltnet/smtm`
- `https://smtm.msalt.net`
- `https://nanobot.msalt.net`
- `https://github.com/msaltnet/T.Viewer`
- `https://brunch.co.kr/@msaltnet`
- `https://blog.msalt.net/`

BootstrapMade 출처 링크는 새 디자인에서 제거한다. 외부 콘텐츠 링크는 새 탭에서 열고 `rel="noopener noreferrer"`를 설정한다. 이미지에는 현재 비어 있는 대체 텍스트를 콘텐츠에 맞게 추가한다. 사이트의 canonical URL과 공유 메타데이터는 `CNAME`에 맞춰 `https://msalt.net`으로 통일한다.

## 반응형과 접근성

- 본문 읽기 폭은 약 `680px`로 제한하고 긴 한국어 문장의 줄 길이를 안정적으로 유지한다.
- 작업 목록은 넓은 화면에서 2열, 작은 화면에서 1열로 전환한다.
- 모바일에서도 탐색 항목을 숨기지 않고 짧은 텍스트 링크로 유지한다.
- 키보드 포커스 상태, 충분한 색 대비, 의미 있는 제목 순서와 landmark 요소를 제공한다.
- 사진 위 글자는 배경의 밝기와 관계없이 읽히도록 단색 오버레이를 사용한다.

## 실패 처리와 경계

Jekyll 빌드가 잘못된 front matter나 템플릿 오류를 배포 전에 실패로 드러내게 한다. 글에 대표 이미지가 없어도 레이아웃이 변하지 않으며, 홈은 제목·날짜·description만으로 정상 렌더링된다. 외부 프로젝트가 응답하지 않는 경우에도 홈의 다른 콘텐츠에는 영향을 주지 않는다.

## 검증

- Jekyll 프로덕션 빌드가 오류 없이 끝나는지 확인한다.
- 생성된 홈과 첫 Article 페이지의 내부 링크, 여섯 개 기존 외부 URL, 메타 태그를 검사한다.
- 데스크톱과 모바일 뷰포트에서 Playwright 스크린샷을 확인한다.
- 첫 화면에서 산 사진, 이름, 최신 기록의 시작이 함께 보이는지 확인한다.
- 텍스트 겹침, 가로 스크롤, 이미지 누락, 빈 링크가 없는지 확인한다.
- 키보드 탐색과 `prefers-reduced-motion` 상태를 확인한다.
- 생성된 페이지가 BootstrapMade 및 기존 vendor CSS/JS를 요청하지 않는지 확인한다.

## 제외 범위

CMS, 로그인, 댓글, 뉴스레터, 전문 검색, 태그/카테고리 탐색, RSS 확장은 이번 개편에 포함하지 않는다.
